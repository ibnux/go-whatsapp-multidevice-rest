# Go WhatsApp Multi-Device REST API

## Project Overview

A REST API wrapper around [whatsmeow](https://go.mau.fi/whatsmeow) (Go library for WhatsApp Multi-Device protocol) using the Echo v4 HTTP framework. Provides endpoints for WhatsApp messaging (text, media, polls, etc.), group management, and device authentication via QR code or pairing code.

## Quick Start

```bash
# Build
make vendor  # go mod tidy + go mod vendor
make build   # CGO_ENABLED=0 go build -ldflags="-s -w" -o go-whatsapp-multidevice-rest cmd/main/main.go

# Run with PM2
pm2 restart 1    # restart service after new build
pm2 log 1        # view logs

# Run locally
make run
```

## Architecture

```
cmd/main/main.go              → Entry point: Echo setup, cron init, graceful shutdown
internal/
  route.go                    → All route definitions + JWT config
  startup.go                  → Restore devices from SQLite DB on boot
  routines.go                 → Cron job (60s) checking JID consistency
  index/index.go              → Root endpoint handler
  auth/auth.go                → JWT generation endpoint
  auth/types/                 → Auth request/response types + JWT claims
  whatsapp/whatsapp.go        → All WhatsApp API controllers (thin layer)
  whatsapp/types/             → WhatsApp request/response types
pkg/
  env/env.go                  → Env variable helpers (godotenv/autoload)
  log/log.go                  → logrus structured logger
  router/*.go                 → Echo config, response helpers, middleware, cache
  auth/*.go                   → BasicAuth middleware, JWT secret loading
  whatsapp/
    whatsapp.go               → Core WhatsApp client manager & message sending
    version.go                → Client version tracking
    drivers.go                → SQLite driver registration (import side-effect)
dbs/                          → SQLite database (WhatsApp.db, auto-created)
docs/                         → Swagger docs (generated by `make gen-docs`)
```

## ⚠️ Critical Issues: Message Sync & Client Stability

### Current Problems

1. **No event handlers registered on whatsmeow client** — The client is created at `pkg/whatsapp/whatsapp.go:WhatsAppInitClient()` but **`AddEventHandler()` is never called**. This means:
   - Incoming messages are never received or processed
   - No read/delivery receipts are sent back
   - WhatsApp servers detect the client as inactive/stale
   - History sync from primary device is never acknowledged
   - The client may appear as "web client" but doesn't function as one

2. **No connection health monitoring** — After `Connect()`, there's no tracking of:
   - Disconnection events & auto-reconnect success/failure
   - Stream replacement (another client logs in)
   - Logged-in/logged-out state transitions
   - Identity changes

3. **Cron job is minimal** — `internal/routines.go` only checks JID mismatch every 60s. It doesn't verify actual connection health or attempt reconnection.

4. **No graceful degradation** — When a client fails, errors propagate as `"WhatsApp Client is not Valid"` without attempt to reconnect.

### What Needs to Be Fixed

#### 1. Register Event Handler on Client Creation

In `pkg/whatsapp/whatsapp.go`, after creating the client, register an event handler:

```go
WhatsAppClient[jid].AddEventHandler(func(evt interface{}) {
    switch v := evt.(type) {
    case *events.Message:
        // Handle incoming message
        // - Send read receipt
        // - Log/forward the message
        // - Update last activity timestamp
    case *events.Receipt:
        // Handle delivery/read receipts
    case *events.Connected:
        // Track connection state, set presence
    case *events.Disconnected:
        // Log disconnection, attempt reconnect
    case *events.LoggedIn:
        // Update stored JID
    case *events.Logout:
        // Clean up client map
    case *events.HistorySync:
        // Acknowledge history sync from primary device
        // Mark RequireFullSync as handled
    case *events.StreamReplaced:
        // Another client took over — log and clean up
    case *events.PairSuccess:
        // Pairing completed successfully
    }
})
```

#### 2. Implement Proper Message Receipt Handling

WhatsApp expects clients to acknowledge received messages. Add a function to send read receipts:

```go
func WhatsAppMarkRead(jid string, chatJID types.JID, messageIDs []string) error {
    receipt, err := WhatsAppClient[jid].MarkRead(context.Background(), messageIDs, time.Now(), chatJID, "")
    // ...
}
```

#### 3. Set Proper Client Properties for Web Client

```go
store.DeviceProps.RequireFullSync = proto.Bool(true) // Enable history sync
store.DeviceProps.PlatformType = waCompanionReg.DeviceProps_CHROME // Stay as Chrome
```

#### 4. Enhanced Connection Health Check

Add a routine that:
- Pings the WebSocket connection periodically
- Attempts auto-reconnect on disconnect (keep `EnableAutoReconnect = true`)
- Logs connection state changes

#### 5. Event Handler Infrastructure

Create a dedicated file like `pkg/whatsapp/handler.go` for event handling logic to keep `whatsapp.go` focused on client management and message sending.

## API Endpoints

All endpoints under `{HTTP_BASE_URL}` (default: `/api/v1/whatsapp`).

### Auth
- `GET /auth` — BasicAuth → returns JWT token
- `POST /login` — JWT required → QR code for device pairing
- `POST /login/pair` — JWT required → pairing code
- `POST /logout` — JWT required → logout device

### Send Message
- `POST /send/text` — Text message
- `POST /send/location` — Location (lat/lng)
- `POST /send/contact` — Contact (name + phone)
- `POST /send/link` — Link with preview
- `POST /send/document|image|audio|video|sticker` — Media
- `POST /send/poll` — Poll creation

### Message Management
- `POST /message/edit` — Edit message
- `POST /message/react` — React to message
- `POST /message/delete` — Delete/revoke message

### Group
- `GET /group` — List joined groups
- `POST /group/join` — Join via invite link
- `POST /group/leave` — Leave group

### Info
- `GET /registered` — Check if number is on WhatsApp

## Code Patterns

### Error Handling
Guard clauses with early returns. Service layer returns Go errors; controller converts to HTTP responses using `router.Response*` helpers.

```go
if err != nil {
    return router.ResponseInternalError(c, err.Error())
}
```

### Logging
```go
import "github.com/dimaskiddo/go-whatsapp-multidevice-rest/pkg/log"

log.Print(c).Info("message")   // With request context
log.Print(nil).Info("message") // Without context
```

### JWT Payload Extraction
```go
func jwtPayload(c echo.Context) typAuth.AuthJWTClaimsPayload {
    jwtToken := c.Get("user").(*jwt.Token)
    jwtClaims := jwtToken.Claims.(*typAuth.AuthJWTClaims)
    return jwtClaims.Data
}
```

### Response Format
All responses follow this structure:
```go
type ResSuccessWithData struct {
    Status  bool        `json:"status"`
    Code    int         `json:"code"`
    Message string      `json:"message"`
    Data    interface{} `json:"data"`
}
```

### Global State
```go
var WhatsAppDatastore *sqlstore.Container                  // SQLite store (init in init())
var WhatsAppClient = make(map[string]*whatsmeow.Client)    // JID → Client map
```

## Common Pitfalls

1. **No event handlers** — The client immediately created but never listens for events. This is the #1 stability issue.
2. **Nil pointer on client lookup** — Direct map access `WhatsAppClient[jid]` without checking existence can panic.
3. **Presence toggling on every send** — `WhatsAppSend*` functions toggle presence to available then back to unavailable, which is unnecessary overhead.
4. **Duplicate `WhatsAppClient[jid] != nil` checks** — Some functions check this twice (once at top, once for `Store.ID`).
5. **Import path uses `dimaskiddo`** — All imports use `github.com/dimaskiddo/go-whatsapp-multidevice-rest/...`. The `Makefile` has a `rebase` target to replace these.
6. **Tests don't exist** — `make test` is not configured; README confirms "not ready yet".

## Database

Uses SQLite via `modernc.org/sqlite` (pure Go, no CGO needed). The whatsmeow library stores device sessions, contacts, and messages in `dbs/WhatsApp.db`. The schema is managed automatically by whatsmeow's `sqlstore.Container`.
